# Header craft review — popup.html (Celine, 2026-09-10)

## ONE recommendation
**Make the header chrome, not a card.** Set `.header { background: var(--surface-body) }`, drop the
`border-bottom` hairline entirely, demote the wordmark to `--text-secondary`, and shorten it to
**"Token Tracker"**. The header should be the frame the meter tile floats in — right now it is a
fifth tile that lost its rounding and outranks the thing you opened the popup to read.

## Findings, worst first

**1. The header competes with the hero (severity: high).**
`.header` uses `--surface-tile` #252320 — the exact fill of `.tile` and `#meterTile`. The only
separation is `1px --hairline-soft`. So the top 44px reads as tile-adjacent content, and
`#meterTile`'s `box-shadow: 0 2px 8px` — the deliberate "primacy is carried by ONE signal" call in
your own comment — is undercut by a same-fill slab sitting directly above it. Fix: `--surface-body`.
Not `--surface-hover` (#1f1e1b): that token means *interaction*, and reusing it as a surface breaks
the semantics you set up. With the header at body colour the hairline becomes redundant — content
`padding: var(--sp-4)` already does the separating. Keep a hairline only if the scroll area can go
under it, in which case make it appear on scroll, not at rest.

**2. "Claude Token Tracker" doesn't earn 15px serif (high).**
In a Chrome popup the extension's identity is already established by the icon the user just clicked.
Three words at Cormorant 15px `--text-primary` puts brand at the same tonal weight as the 42px
verdict number. Nothing in the 2-second glance ("keep going or wrap up") is served by the word
"Claude" — the user is on claude.ai. Cut to "Token Tracker", `--text-secondary`, 13px. Keep the
serif: it's the one thread tying header to `.meter-val`, and dropping it would leave the logo
orphaned. Logo-only is the aggressive option and defensible, but the 20px `logo.svg` with
`border-radius: 4px; object-fit: cover` is a favicon crop, not a mark — it can't carry identity alone.

**3. Refresh is the primary action rendered as tertiary chrome (high).**
The single most common intent — "is this number current?" — is a 14px stroke icon in a 34px circle,
visually equal to Settings, a thing touched twice ever. Two moves, in order of appetite: (a) give
refresh `--text-primary` at rest and leave settings `--text-secondary`; (b) better — pair it with the
`#meterUpdated` freshness line and let *that* be the refresh trigger inside the tile, leaving the
header with settings only. (b) is the stronger design: it puts the action next to the data whose
staleness motivates it. If you keep both, add `gap: var(--sp-1)` to `.hdr-actions` — the buttons
currently touch, which reads as a segmented control they aren't.

**4. Wrong icon for Settings (medium).**
Sliders/equalizer is the near-universal glyph for *filters/adjust*, not settings. Users will expect a
filter panel and get a drawer. Use a gear. Cheap fix, real mental-model cost.

**5. Hit target + a11y (medium).**
34×34 misses the 44px minimum; `title` is not an accessible name for a screen reader in practice and
never appears on keyboard focus. Add `aria-label` to both buttons, `aria-hidden="true"` to both SVGs,
and `aria-expanded` on `#btnSettings` (which already has an `.active` state — that state exists but is
unannounced). Keep the 34px visual and add `::before` padding to reach 44px, or just go 40px.

**6. `.hdr-btn.active` coral is too loud (low).**
`--coral` + `--coral-glow` on a persistently-open drawer creates a standing hotspot in a UI whose only
other coral is focus. Since the drawer's presence is self-evident, `--text-primary` + `--surface-hover`
is enough. Reserve coral for focus and truly current state.

**7. Motion is nearly right (low).**
`spinOnce 340ms` is a good length, but `--ease-out` (cubic-bezier(0.16,1,0.3,1)) on a full rotation
means it *finishes* almost instantly and then hangs — a spin should be near-linear, or ease-in-out if
it's one shot. Change to `linear`. `scale(0.92)` on 34px is a 2.7px travel — under-read; on a small
target use `0.88`. Also: none of `spinOnce` or the press respects `prefers-reduced-motion` — add a
media query that kills the rotation (swap for a brief opacity dip).

## Missing states
- Refresh **in-flight** beyond one spin — if the fetch takes >340ms the icon stops while the app is
  still working. Loop the spin while `.refreshing` is on `<body>`.
- Refresh **failed** — `#apiBroken` covers the whole popup, but a transient failure needs an
  in-header signal (icon → `--danger` for ~1.5s).
- **Offline / not authenticated** — when `#authState` is shown, refresh is the CTA the copy points at
  ("then click refresh") but nothing in the header marks it as the target.
- **Focus-visible on the wordmark region** — non-issue only if nothing there is focusable; confirm.

## Confidence
High on 1, 2, 3, 4, 5 (these are structural/convention calls with clear reasoning).
Medium on 3(b) — moving refresh into the tile is the better design but is a bigger change and worth
prototyping against 3(a) first. Medium on 6 — depends on whether the drawer is visually obvious.
