# Celine — meter tile craft review (2026-09-10)
Scope: `popup/popup.html` (inline CSS) + `popup/popup.js` L145–200. Review only.

## THE ONE RECOMMENDATION
**Collapse the number and the verdict into one two-part hero line, and let the number carry the state colour.**

Today the tile has two competing heroes: `.meter-val` (42px serif, neutral white at ok) and `.meter-verdict` (13px/600, the only green thing in the tile). Size says "look at 32%"; colour says "look at Plenty left". At a 2-second glance the eye ping-pongs. Both encode the *same* variable — `st` in popup.js drives both — so this is one signal rendered twice at two levels.

Fix:
- `.meter-val.ok { color: var(--success); }` — the number carries state at all three levels (ok/warn/bad), matching the bar it sits above. Neutral-white-at-ok is a defensible restraint argument, but it costs you the thing you actually want: state readable pre-attentively, from colour, at hero size.
- Demote the verdict to the suffix slot: one baseline row `32% used · Plenty left`, verdict at 12px/500 in `--text-secondary`, **not** 600 and not coloured. It becomes a caption on the number, not a rival.
- If you want the verdict to stay bold and coloured, then the number must go neutral *and small* — pick one hero. Do not run both hot.

Squint result today: 1st the 42px number, 2nd the green verdict word (colour beats size at small area), 3rd the bar, 4th the mono countdown. Correct order is number(+state) → bar → countdown → foot. The countdown is currently the weakest-served important item: "resets in 2h 14m" is half the decision ("wrap up" only makes sense against *when relief arrives*) and it's rendered at 11px `--text-secondary` mono, below the verdict, above the bar — buried mid-stack.

## Prioritized rest

1. **Levels are muddy — five, should be three.** `.meter-verdict` 13/600, `.meter-val-suffix` 13/500, `.meter-countdown` 11px secondary, `.meter-foot` 10px secondary, `.meter-updated` 10px faint. Three of those sit in one narrow band (10–13px, secondary). Resolve to: **P** number+state; **S** bar + countdown; **A** foot + updated, both at `--text-faint`. Concretely: move `.meter-foot` from `--text-secondary` to `--text-faint` — it's a static label ("5-hour window") plus a secondary metric, and it currently reads at the same tonal weight as the countdown, which is a live decision input.

2. **Spacing has no grouping.** 4 / 4 / 12 / 12 / 4 is nearly flat — two gap sizes for five joints reads as one undifferentiated stack. Ideal: **2px** number→verdict (or zero, if merged), **10px** to countdown, **16px** to bar, **8px** bar→foot, **4px** foot→updated. That's tight-inside-group, generous-between-group, and it makes the bar the visual hinge between "the read" and "the footnotes". Selectors: `.meter-verdict{margin:0 0 2px}`, `.meter-countdown{margin-bottom:var(--sp-4)}`, `.bar-track{margin-bottom:var(--sp-2)}`.

3. **Meter vs trend tile: not enough separation.** Both are `.tile`, `#252320`, `--r-lg`; only `#meterTile{border:1px solid var(--hairline-soft)}` differs — a 1px `#322f2b` edge on `#252320` is ~invisible. Give the meter `padding: var(--sp-5)` (trend already runs `sp-3` inline) and a real elevation cue: `box-shadow: 0 1px 0 rgba(255,255,255,0.04) inset, 0 2px 8px rgba(0,0,0,0.35)`. Size + shadow does what the hairline is failing to do. Also promote the meter with a section-heading *absence* — the trend has a `.sec-h`, the meter doesn't; that asymmetry is correct, keep it.

4. **Bar is under-built for the hinge role.** 6px tall, full-bleed, no reference marks. Add a hairline tick at 100%-of-window and consider 8px height. It's the only spatial encoding in the tile; at 6px it reads as trim.

5. **Colour is doing too little, in one wrong place.** State colour appears on exactly two elements (verdict text, bar fill) and never on the number. Meanwhile `--coral` — declared "interactive only" — is correctly absent here. Good discipline. But `.trend-stats .val.coral { color: var(--danger); }` is a naming lie that will bite; rename to `.val.red`.

6. **`.meter-advisory` renders below `.meter-updated`.** Advice sits under a timestamp. Move it directly under the bar — it's a decision input, not a footnote. HTML order fix, no CSS.

7. **`--text-faint #8f8c85` at 10px** (`.meter-updated`, `.spark-days`, `.hourly-labels`) is ~4.6:1 — passes for normal text but 10px is below the "large text" allowance and this is a squint-read surface. 11px minimum for anything faint.

**Confidence: high** on 1–3 and 6 (structural, provable by squint). **Medium** on 4 and 7 (taste/threshold calls).
